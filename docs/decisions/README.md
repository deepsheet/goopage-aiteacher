# 架构决策记录（ADR）

本目录记录**重要技术选择及其原因**。ADR 解释「为什么这样选、放弃了什么」，与描述「现在是什么样」的 [architecture.md](../architecture.md) 分工不同。

## 收录标准

只有当决策原因能被**代码、配置、Git 历史或已有文档**证明时才写 ADR。无法证明原因的选择不要虚构，宁可留在 `architecture.md` 的「技术约束」或「已知技术债」里，或标为待确认。

值得写：影响面大、难以逆转、有多个合理备选、后来者一定会问「为什么不用 X」。
不值得写：常规实现细节、纯样式问题、随时可改的小开关。

## 如何新增

1. 复制任一现有 ADR 的结构，文件名 `ADR-NNN-短横线英文名.md`，编号取当前最大值 +1（编号不复用、不重排）。
2. 按模板填写：状态 / 日期 / 背景 / 决策 / 依据 / 放弃的方案 / 影响与代价。
3. **依据**一节必须给出可核对的代码位置或文件，不能只写理由。
4. 在上方表格追加一行，并从相关正文文档链过来（正文只摘要 + 链接，不复制论证）。
5. 决策被推翻时不要把文件删掉：把状态改为「已废弃」并注明被哪一份 ADR 取代。

ADR 一旦写入即视为历史记录，后续修订优先新增而不是改写旧文。
